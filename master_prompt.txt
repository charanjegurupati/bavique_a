# MASTER PROMPT: BAVIQUE — Premium Girls' Accessories Catalogue Website

## 1. Your Role

Act as a **senior UI/UX designer, senior full-stack developer, security engineer, database architect, and QA tester**. Build a complete, polished, production-ready website for **BAVIQUE — Fancy, Beauty, Fashion**.

Do not create only a static design or landing-page prototype. Build a functional website with a connected backend, database, secure admin dashboard, product image uploads, working category filters, and complete testing.

## 2. Business Overview

**Brand name:** BAVIQUE  
**Tagline:** More than just a store… it's a vibe.

**Business type:** A local girls' accessories, beauty, jewellery, and fashion store.

**Purpose:** Create an attractive online catalogue that allows customers to discover products available in the physical store.

### Critical business rule

This is a **product-display-only website, NOT an e-commerce website**.

- Customers can view product images, descriptions, prices, categories, and availability.
- Customers cannot purchase products online.
- Do not implement checkout, shopping carts, online payments, delivery orders, or order management.
- Do not create unnecessary customer registration or login.
- Only the store owner or authorized administrators need to log in to manage the catalogue.

The website should help customers discover products before visiting the physical store.

Use subtle animations, smooth transitions, and polished interactions. Avoid excessive neon colors, distracting animations, clutter, or a generic e-commerce template.

## 10. Complete Security Checklist

Treat security as a mandatory release requirement, not an optional improvement.

### Authentication and authorization

- Hash administrator passwords using Argon2id or an appropriately configured bcrypt implementation.
- Never store or return plaintext passwords.
- Do not hardcode credentials or expose secrets in frontend code.
- Keep admin registration disabled publicly.
- Protect every administrative API route with server-side authentication and authorization.
- Verify ownership or permissions on every protected operation.
- Use secure, HttpOnly, SameSite cookies for browser sessions where appropriate.
- Use HTTPS and secure cookie settings in production.
- Implement session expiration, logout invalidation, and safe password-reset tokens.
- Add login rate limiting and reasonable lockout or throttling controls.
- Protect cookie-authenticated state-changing requests against CSRF.
- Never rely on hiding admin buttons as an authorization mechanism.

### Input validation and common web vulnerabilities

- Validate all inputs on both the frontend and backend.
- Sanitize or safely render untrusted text to prevent stored and reflected XSS.
- Use Mongoose safely and avoid unsafe query construction.
- Prevent mass-assignment vulnerabilities by explicitly allowing editable fields.
- Configure CORS with specific trusted origins.
- Apply suitable security headers using Helmet.
- Apply request-size limits and rate limiting.
- Avoid leaking stack traces, credentials, database errors, or internal paths.
- Keep dependencies updated and review known vulnerabilities.
- Never expose database connection strings, API keys, or cloud credentials.

### Secure image uploads

- Accept only explicitly supported image formats.
- Verify file signatures and actual image content rather than trusting file extensions or MIME headers alone.
- Enforce file-size, image-dimension, and image-count limits.
- Generate safe filenames and avoid executing uploaded content.
- Reject SVG or other active content unless it is safely sanitized and explicitly supported.
- Re-encode images where appropriate and generate optimized thumbnails.
- Use a managed storage service with appropriate access controls.
- Validate uploaded files on the server before publishing them.
- Restrict image transformations and storage permissions.
- Handle upload failures and abandoned files safely.

### Data protection and operational security

- Use environment variables or a managed secrets service.
- Restrict database access to the application's required permissions.
- Use database backups and document a recovery procedure.
- Avoid collecting unnecessary customer personal information.
- Do not add customer accounts, payment details, or order records because this website does not sell online.
- Maintain appropriate administrator activity logs for logins, product changes, and deletions.
- Do not log passwords, session tokens, or secret values.
- Provide safe error handling and monitoring without exposing private information.
- Use least-privilege permissions for hosting, database, and image storage.

Before deployment, verify these protections against the actual implementation. Do not claim the site is completely secure simply because the checklist exists.
